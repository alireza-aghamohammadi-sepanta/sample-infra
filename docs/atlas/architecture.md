# Cloud Infrastructure Architecture

The infrastructure architecture for the sample application stack is built on a serverless, managed-services foundation hosted on Google Cloud Platform. It minimizes operational overhead by leveraging fully managed compute, database, and storage platforms while enforcing strict isolation, least-privilege IAM bindings, and secure cross-service communication.

### 1. Ingress Tier
Traffic from external clients arrives over TLS 1.3. Google Cloud Run automatically manages public ingress, certificates, and traffic load balancing across active container instances without requiring self-managed ingress controllers.

### 2. Presentation Tier
The frontend is deployed as a lightweight, unprivileged container on [Compute](compute.md). It hosts the compiled React 18 single-page application through an optimized Nginx server configured with:
- Client-side routing fallback (`try_files $uri $uri/ /index.html`).
- Gzip compression for static assets (`.js`, `.css`, `.svg`).
- Modern security response headers (CSP, HSTS, X-Frame-Options).

### 3. Application API Tier
The backend runs as a containerized FastAPI application on [Compute](compute.md). It handles authentication, task management, and asset metadata. Features include:
- Multi-stage Docker image built with Astral `uv` on Python 3.13 Bookworm-slim.
- Concurrency and autoscaling from zero up to configured service caps.
- Cloud SQL Connector integration for zero-secret IAM database connectivity.

### 4. Object Storage Tier
User attachments are offloaded from application memory and network pipes directly to [Object Storage](storage.md):
- Direct browser uploads via V4 signed upload URLs generated by the backend.
- Bucket CORS configuration allowing PUT requests with authorized headers (`Content-Type`).
- Uniform bucket-level access preventing accidental public disclosure of uploaded assets.

### 5. Relational Database Tier
Application state, user accounts, and todo records persist in a managed [Database](database.md):
- Google Cloud SQL instance running PostgreSQL 16.
- Connection authentication mediated by Cloud SQL IAM database authentication, replacing static long-lived database passwords.
- Integrated schema migration pipeline leveraging Alembic.

### 6. Secrets & Identity Tier
Configuration and authorization boundaries are enforced via [Security](security.md):
- Dedicated IAM service accounts for compute services with minimal necessary roles.
- Google Cloud Secret Manager storing sensitive values (e.g. `JWT_SECRET`, mail relay credentials) consumed during application startup.
